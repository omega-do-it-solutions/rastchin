# یکپارچه‌ساز دسکتاپ راست‌چین

یکپارچه‌ساز دسکتاپ راست‌چین، برنامهٔ دسکتاپ در [مونوریپوی عمومی راست‌چین](https://github.com/omega-do-it-solutions/rastchin) است. این برنامه یک ابزار همراه محلی برای بهتر کردن خوانایی فارسی در rendererهای دسکتاپ پشتیبانی‌شدهٔ ChatGPT/Codex روی ویندوز، macOS و لینوکس است. زبان طبیعیِ تحت پشتیبانی فقط فارسی است. برنامه Claude Desktop را تشخیص می‌دهد، اما یکپارچه‌سازی آن را برای انتشار آینده برنامه‌ریزی‌شده نشان می‌دهد، زیرا میزبان فعلی اتصال استایل‌دهی پشتیبانی‌شده‌ای ارائه نمی‌کند. این برنامه یک کلاینت هوش مصنوعی دیگر نیست؛ کاربران همچنان در برنامه‌های رسمی کار می‌کنند.

## وضعیت فعلی

یکپارچه‌سازی ChatGPT/Codex در این برنامه **پایدار** است. ساخت‌های بسته‌بندی‌شده، یکپارچه‌سازی runtime را بدون نیاز به ترمینال یا متغیر محیطی فعال می‌کنند.

- کشف ویندوز، macOS و لینوکس با بررسی‌های ویژهٔ پلتفرم برای هویت، بسته، مسیر، معماری و مجوز پیاده‌سازی شده است. در لینوکس، برنامهٔ فروشنده را فقط از OpenAI نصب کنید؛ فرادادهٔ محلی DEB به‌تنهایی نمی‌تواند منشأ آن را به‌صورت رمزنگاری‌شده اثبات کند.
- استایل‌دهی runtime در ChatGPT/Codex برای هر سه پلتفرم پشتیبانی و با چک‌لیست دود ویژهٔ همان پلتفرم اعتبارسنجی می‌شود.
- ساخت‌های فعلی Claude Desktop اتصال خصوصی اشکال‌زدایی Chromium لازم برای استایل‌دهی در حافظه را صریحاً رد می‌کنند. راست‌چین این حفاظت میزبان را دور نمی‌زند؛ کارت Claude غیرفعال است و پشتیبانی را برای انتشار آینده نشان می‌دهد.
- رابط مدیر فارسی‌محور است، با فونت Vazirmatn همراه برنامه به‌صورت RTL رندر می‌شود و مقادیر فنی را از نظر جهت جدا نگه می‌دارد.
- runtime مشترک RTL، پیام‌ها، فهرست‌ها، محافظت از کد، به‌روزرسانی streaming، تایپوگرافی Vazirmatn، متن ترکیبی و composer فارسی را مدیریت می‌کند.
- کارت‌های پرسش تعاملی و تأیید Codex از adapter معنایی ویژه استفاده می‌کنند: عنوان، توضیح و ردیف گزینه‌های فارسی RTL می‌شوند و label انگلیسی، پیوند، کد، input، آیکن و هندسهٔ کنترل جدا می‌مانند.
- shellهای محلی Electron renderer جدا از DOM وب عمومی تشخیص داده می‌شوند و adapterهای محدودتر وب عمومی در صورت وجود selector دقیق حفظ می‌شوند.
- غیرفعال‌سازی، تغییرات DOM جلسهٔ فعال renderer را برمی‌گرداند.
- فایل‌های امضاشدهٔ MSIX، بسته‌های برنامهٔ macOS، فایل‌های بستهٔ لینوکس، `app.asar` و پوشه‌های نصب فروشنده هرگز تغییر نمی‌کنند.
- هر ساخت بسته‌بندی‌شده allowlist صریح پلتفرم و سیاست runtime ثبت‌شده دارد.
- `RASTCHIN_DISABLE_RUNTIME_INJECTION=1` راهکار اضطراری محلی است.

| پلتفرم | ChatGPT / Codex | Claude Desktop |
| --- | --- | --- |
| ویندوز | پایدار | تشخیص داده می‌شود؛ یکپارچه‌سازی را میزبان مسدود می‌کند |
| macOS 14+ | پایدار | تشخیص داده می‌شود؛ یکپارچه‌سازی را میزبان مسدود می‌کند |
| لینوکس پشتیبانی‌شده | پایدار | تشخیص داده می‌شود؛ یکپارچه‌سازی را میزبان مسدود می‌کند |

دسترس‌پذیری فروشنده، نیازمندی پلتفرم و جزئیات داخلی برنامه با زمان تغییر می‌کند. پیش از انتشار، نگه‌دارندگان باید مستندات رسمی فعلی فروشنده را با قواعد allowlist بسته، هویت و آزمون دود راست‌چین مقایسه کنند. راست‌چین فقط برای ترکیب‌هایی ادعای پشتیبانی می‌کند که این بررسی‌ها را می‌گذرانند. یکپارچه‌سازی‌های فعلی برای استایل‌دهی رابط گفت‌وگوی موجود، به API مستندشدهٔ فروشنده تکیه ندارند.

## گردش‌کار مورد انتظار کاربر

1. یکپارچه‌ساز دسکتاپ راست‌چین را نصب و باز کنید.
2. راست‌چین برنامه‌های رسمی دسکتاپ و نسخهٔ آن‌ها را تشخیص می‌دهد.
3. برای ChatGPT/Codex، برنامهٔ در حال اجرا را ببندید و روی **فعال‌سازی راست‌چین** کلیک کنید.
4. راست‌چین ChatGPT/Codex را باز می‌کند و RTL را در حافظه اعمال می‌کند.
5. تا زمانی که یکپارچه‌سازی فعال است، راست‌چین را در tray/menu bar باز نگه دارید.
6. برای حذف استایل‌ها و observerهای تزریق‌شده، روی **Disable RTL** کلیک کنید.
7. ‏Claude Desktop به‌عنوان هدف تشخیص‌داده‌شده دیده می‌شود، اما اکشن آن غیرفعال و برای انتشار آینده علامت‌گذاری شده است.

بستهٔ غیرمنتظره و چیدمان ناشناختهٔ renderer به‌صورت امن رد می‌شوند. راست‌چین فایل‌های برنامهٔ فروشنده را patch نمی‌کند.

## توسعه

از Node.js 24 و pnpm 11.14.0 استفاده کنید. فضای کاری مشترک را یک‌بار از ریشهٔ مونوریپو نصب کنید:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm --filter rastchin-desktop-integrator test
pnpm --filter rastchin-desktop-integrator verify
pnpm --filter rastchin-desktop-integrator dev
```

برای فعال‌سازی runtime در یک ساخت توسعه از سورس:

```bash
pnpm --filter rastchin-desktop-integrator dev:runtime
```

پیش از اجرای probe مربوط به ChatGPT، آن را ببندید. Claude Desktop تشخیص داده می‌شود، اما با اتصال اشکال‌زدایی اجرا نمی‌شود. راست‌چین را با دسترسی root/Administrator اجرا نکنید و مجوز پوشه‌های نصب فروشنده را تغییر ندهید. از چک‌لیست مرتبط استفاده کنید: [ویندوز](docs/WINDOWS-SMOKE.md)، ‏[macOS](docs/MACOS-SMOKE.md) یا [لینوکس](docs/LINUX-SMOKE.md).

اگر probe شکست خورد، برنامهٔ رسمی را فقط به‌اندازهٔ بررسی پنل **Renderer diagnostics** باز نگه دارید و پیش از تلاش دوباره آن را کاملاً ببندید. راست‌چین در هر تلاش وضعیت فرایند را دوباره اسکن می‌کند. عیب‌یابی فقط شامل نوع هدف، URL پالایش‌شدهٔ renderer و تعداد elementها است؛ عنوان و متن گفتگو جمع‌آوری نمی‌شود.

## معماری

```text
رابط مدیر Electron
  -> کشف فقط‌خواندنی پلتفرم + بررسی هویت فروشنده
  -> ChatGPT/Codex: بررسی نسخه/چیدمان -> انتقال خصوصی runtime
     -> fallback پوستهٔ دسکتاپ + adapter برنامهٔ ChatGPT + adapter کارت پرسش Codex
        -> موتور مشترک RTL
  -> Claude Desktop: وضعیت مسدودشده توسط میزبان -> حالت غیرفعال تا انتشار آینده
```

فرایند همراه فقط وضعیت پروتکل و تعداد selectorها را دریافت می‌کند. تشخیص جهت داخل renderer انجام می‌شود؛ متن پیام و prompt به مدیر برنمی‌گردد و از شبکه ارسال نمی‌شود. جزئیات بیشتر در [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) آمده است.

این برنامه مالک composition نرم‌افزار Electron، کشف پلتفرم، بررسی اعتماد، انتقال پایپ خصوصی، تزریق renderer، رابط مدیر، آزمون و دارایی بسته‌بندی خود است. اشتراک میان برنامه‌ها باید از یک بستهٔ عمدی فضای کاری عبور کند؛ برنامه‌های دیگر نباید فایل‌های این پوشه را مستقیماً import کنند.

## بسته‌بندی

پیش از بسته‌بندی آزمون و راستی‌آزمایی را اجرا کنید:

```bash
pnpm install --frozen-lockfile
pnpm --filter rastchin-desktop-integrator test
pnpm --filter rastchin-desktop-integrator verify
```

روی سیستم‌عامل هدف بسازید:

```bash
pnpm --filter rastchin-desktop-integrator package:win
pnpm --filter rastchin-desktop-integrator package:mac
pnpm --filter rastchin-desktop-integrator package:linux
```

فرمان `package:mac` و گردش‌کار عادی CI مربوط به macOS، خروجی داخلی با امضای ad-hoc می‌سازند. CI بستهٔ کامل برنامه را پیش از بسته‌بندی و از داخل هر DMG بررسی می‌کند. امضای ad-hoc ساختار برنامه را معتبر می‌کند، اما اعتماد Developer ID یا notarization فراهم نمی‌کند.

برای دانلود نهایی کاربر Mac، اعتبارنامه‌های Developer ID و notarization اپل را مطابق `docs/MACOS-SMOKE.md` تنظیم و سپس اجرا کنید:

```bash
pnpm --filter rastchin-desktop-integrator package:mac:release
```

خروجی‌ها:

- `RastChin-Desktop-Integrator-Setup-<version>-<arch>.exe`
- `RastChin-Desktop-Integrator-Portable-<version>-<arch>.exe`
- `RastChin-Desktop-Integrator-<version>-macOS-<arch>.dmg`
- `RastChin-Desktop-Integrator-<version>-macOS-<arch>.zip`
- `RastChin-Desktop-Integrator-<version>-Linux-<arch>.AppImage`
- `RastChin-Desktop-Integrator-<version>-Linux-<arch>.deb`
- `RastChin-Desktop-Integrator-<version>-Linux-<arch>.rpm`

خروجی‌های بسته‌بندی‌شده سیاست runtime را در خود دارند و با اجرای عادی کار می‌کنند؛ کاربران متغیر محیطی توسعه را تنظیم نمی‌کنند.

ساخت امضانشدهٔ ویندوز ممکن است هشدار SmartScreen ایجاد کند. خروجی‌های داخلی macOS با امضای ad-hoc ممکن است همچنان به تأیید صریح **Open Anyway** نیاز داشته باشند. ساخت عمومی macOS به امضای Developer ID، ‏notarization و stapling نیاز دارد؛ گردش‌کار `macOS signed release` این مسیر را اجباری می‌کند. کاربران لینوکس بهتر است DEB یا RPM سازگار با توزیع خود را انتخاب کنند؛ AppImage گزینهٔ قابل‌حمل است.
